# 🏛️ Основні принципи та маніфест архітектури: JARVIS Core

## 1. Місія та сфера застосування системи
JARVIS Core — це автономна, керована подіями платформа кількісного аналізу та виконання. Система розроблена для:
- Оркеструвати високопродуктивні фінансові потоки та алгоритмічні механізми прийняття рішень.
- Забезпечувати безперервну операційну стійкість, автоматичну ізоляцію несправностей та адаптивне відновлення продуктивності.

## 2. Архітектурні інваріанти та філософія виконання
- Точність рівня AST: Ядро використовує інтроспекцію абстрактного синтаксичного дерева (AST) для оцінки топології модулів та цілісності коду з мінімальними витратами пам'яті.
- Збереження контракту: Будь-яке операційне оновлення або динамічний патч повинні зберігати функціональні інтерфейси та сигнатури типів, щоб усунути каскадні помилки середовища виконання.
- Самовідновлення та автоматизоване відновлення стану: Винятки та операційні аномалії діють як детерміновані тригери для ізольованих конвеєрів відновлення (`AtomicRollback` та перевірки в пісочниці).
- Сувора гігієна дискового простору та телеметрії: Системні журнали та потоки телеметрії обмежені суворими ковзними буферами (ліміт 1 МБ) без генерації нестисненого сміття. Довгостроковий стан зберігається виключно у структурованих аналітичних сховищах (DuckDB) та векторних базах знань.

## 3. Еволюційний вектор та проактивна телеметрія
- Профілювання вузьких місць: Проактивна телеметрія постійно перевіряє затримки на асинхронній шині подій, щоб запобігти падінню пропускної здатності до досягнення критичних лімітів виконання.
- Автономна консолідація знань: Під час станів очікування (idle), телеметричні дайджести та шаблони виконання консолідуються в структуровані аналітичні представлення.
- Розподілений шлюз телеметрії: Ядро безпечно взаємодіє через шлюзи HTTPS та WebSocket для потокової передачі робочого стану та телеметрії в режимі реального часу на авторизовані термінали.

## 4. Заходи безпеки, ізоляції та виконання
- Ізоляція облікових даних із нульовою довірою (Zero-Trust): Усі токени автентифікації, секрети API ринкових майданчиків та криптографічні ключі суворо ізолюються під час ініціалізації системи та залишаються повністю недоступними для аналітичних пісочниць.
- Шлюз детермінованої валідації: Алгоритмічні дії, коригування ринкової експозиції та маршрутизація сигналів повинні пройти детерміновану багаторівневу перевірку ризиків (`PolicyValidator`) перед відправкою на зовнішні майданчики.
- Виконання в ізольованій пісочниці: Динамічні модифікації та автоматизовані тестові процедури виконуються виключно в ізольованих контейнерах з обов'язковим створенням знімків для відкату (snapshots).
- Динамічне визначення пріоритетів ресурсів: Бюджети обчислень під час виконання керуються динамічно, що гарантує збереження виділених ресурсів процесора для високопріоритетних потоків.

## 5. Інженерні стандарти та якість коду
- Сувора безпека типів: Усі модулі застосовують суворе статичне типізування (семантика Python 3.10+) та явну обробку винятків на всіх операціях вводу/виводу та мережевих межах.
- Хірургічна точність модульних змін: Зміни компонентів реалізуються як ізольовані, атомарні модифікації, а не як монолітні перезаписи.
- Гарантія нульового заповнювача: Компоненти виробничого (production) рівня ніколи не повинні містити усічені реалізації, фіктивну логіку або тимчасові заповнювачі.
